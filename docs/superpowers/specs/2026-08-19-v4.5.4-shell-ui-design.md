# Recruitment Agency v4.5.4 Shell UI Design

## Objective

Correct three user-visible shell design flaws without changing recruitment logic, Scout behavior, API scheduling, data models, forum discovery, candidate workflow semantics, or the v4.5.3 click-interference protection.

The approved approach is a targeted shell correction.

## Current state

The managed `#ra-app` window is fixed-position, movable and resizable. The shell uses a 44 px title bar, a grid with sidebar and main content, and `.ra-content` already declares `overflow:auto` and `flex:1`.

The practical scrolling defect exists because the flex/grid descendants are not sufficiently constrained to shrink within the managed window. Long routed pages can therefore grow beyond the visible content region instead of producing a usable internal vertical scrollbar.

Settings currently has two entry points: the title-bar `#ra-settings-button` and the generated sidebar route. The top-right title-bar Settings button is the desired entry point.

Window geometry is persisted in IndexedDB metadata as `ui.windowGeometry.main` with `x`, `y`, `width`, and `height`. Drag and resize currently save that geometry.

## Scope

### 1. Main-content scrolling

The title bar, sidebar and page header remain stationary inside the RA window. Only the routed page content scrolls vertically.

Required behavior:

- constrain the shell/main flex and grid children so `.ra-content` becomes the real shrinkable scroll container;
- keep `.ra-content` as the primary `overflow:auto` viewport;
- ensure long Settings, Candidates, Scout, Data, Logs and other routed pages can be scrolled to their final content;
- support normal wheel, touchpad, keyboard and scrollbar interaction;
- expose a visible vertical scrollbar in dark and light themes;
- do not turn the entire RA window into a scrolling document;
- preserve horizontal overflow where individual components already require it, such as pipeline/table content.

Implementation should use layout constraints such as `min-height:0` on the relevant shell/main descendants rather than fixed magic heights.

### 2. Settings navigation cleanup

Keep the title-bar `⚙ Settings` control and its existing `route('settings')` behavior.

Remove Settings only from generated sidebar navigation.

Requirements:

- the Settings routed page remains fully available;
- the title-bar Settings button remains visible and functional;
- Data and Logs remain in the sidebar according to existing Simple/Advanced visibility rules;
- routing and active-page normalization remain unchanged;
- direct restoration of `activePage:'settings'` remains supported;
- no other Runtime page definitions need to be removed merely to hide the duplicate sidebar entry.

The preferred implementation is a shell-level navigation filter so the application's route registry remains authoritative and Settings is hidden only from this navigation surface.

### 3. Maximize and Restore

Add a title-bar Maximize control. This is viewport maximize, not the browser Fullscreen API.

Normal title action order:

`Maximize | Settings | mobile menu | Close`

When maximized:

- `#ra-app` fills the browser viewport;
- `left:0`, `top:0`, `width:100vw`, `height:100vh`;
- outer border radius is removed while maximized;
- CSS manual resize is disabled while maximized;
- title-bar dragging does not move the window;
- the control becomes Restore and exposes an appropriate title/aria-label;
- page content remains internally scrollable.

Before maximizing, capture the exact current normal geometry in memory. The persisted normal geometry must not be overwritten by maximized dimensions.

When restored:

- return to the exact pre-maximize `x`, `y`, `width`, and `height`, clamped only if the viewport changed enough to make that geometry invalid;
- re-enable normal drag and resize;
- return the control to Maximize;
- persist the restored normal geometry through the existing geometry mechanism.

Maximized state is intentionally session-only. A reload/new userscript start restores the normal saved geometry rather than automatically reopening maximized.

A ResizeObserver callback caused by entering or leaving maximize must not accidentally save full-viewport geometry as the user's normal geometry.

Viewport resize while maximized must keep the app fitted to the current viewport. Restore must still use the saved normal geometry, clamped to the new viewport if necessary.

## State and architecture

Add only transient shell state required for maximize/restore, for example:

- `maximized: boolean`
- `restoreGeometry: {x,y,width,height} | null`

Do not change IndexedDB version or stores. The existing `ui.windowGeometry.main` record remains the only persisted normal-window geometry.

Maximize behavior should be isolated behind small shell functions rather than spread through route rendering code. Likely responsibilities:

- read current geometry;
- apply maximized presentation;
- restore normal presentation;
- update button label/accessibility state;
- guard drag/resize persistence while maximized.

## Interaction constraints

The v4.5.3 userscript input shield and scoped click-listener bridge must remain compatible with the new Maximize/Restore button.

The new control must be a normal Recruitment Agency button inside `#ra-app` so existing click protection can cover it.

No changes may weaken:

- top-frame restriction;
- singleton DOM ownership;
- legacy UI cleanup;
- disabled-control handling;
- bridged listener removal/once semantics;
- mobile sidebar behavior.

## Responsive behavior

At desktop/tablet widths, maximize fills the viewport exactly.

At mobile widths, existing mobile layout rules still apply to the internal shell. Maximize must not create a second conflicting geometry mode. Since the normal mobile rule already nearly fills the viewport, maximizing may produce only a small visual difference, but Restore must still return to the prior normal mobile geometry.

## Testing

Add regression coverage for all three fixes and retain the complete existing suite.

Required checks:

1. A deliberately tall routed page produces a scrollable `.ra-content` region with `scrollHeight > clientHeight` and can be scrolled to the bottom.
2. The sidebar contains no Settings navigation button.
3. The top-right Settings button still routes to Settings.
4. Maximize changes the app rectangle to the current viewport dimensions and origin.
5. Maximize disables normal dragging/resizing behavior.
6. Restore returns to the pre-maximize geometry within normal browser pixel tolerance.
7. Maximized dimensions are not persisted as `ui.windowGeometry.main`.
8. Resizing the browser viewport while maximized keeps the app viewport-fitted and Restore still returns to valid normal geometry.
9. Existing hostile document-capture click regression still passes for the new control.
10. Existing 421 px mobile regression still passes.
11. Existing isolated-world/singleton and Torn-host physical-click tests still pass.
12. Full unit/runtime/browser suite and JavaScript syntax checks pass before merge.

## Non-goals

This release does not:

- redesign routed page content;
- change Simple/Advanced semantics;
- change recruitment pipeline stages;
- modify DB schema/version;
- change Torn API limits or scheduler behavior;
- change Scout, forum discovery, candidate scoring, Global Intelligence, or messaging logic;
- add browser Fullscreen API behavior;
- persist maximized state across reloads.

## Release

Public userscript/bootstrap release target: `v4.5.4`.

The existing immutable app runtime/version split must be handled consistently with the current release architecture. If the implementation changes a runtime module that is loaded through immutable `@require` URLs, the userscript must pin the resulting tested runtime snapshot rather than silently continuing to reference an older snapshot.
