# v4.5.4 Shell UI Implementation Amendment

## Why the implementation boundary changed

The approved v4.5.4 design requires three shell-level behaviors only: routed-content scrolling, removal of the duplicate sidebar Settings entry, and viewport Maximize/Restore with safe normal-geometry preservation.

The initial implementation plan assumed these changes would be made inside `src/v45-app.js`, which would require publishing and pinning a new immutable copy of the entire v4.5 application runtime.

Inspection during implementation showed that none of the three requirements needs to change recruitment routing semantics, IndexedDB schema, Scout, forum discovery, Smart Match, Global Intelligence, candidate logic, or the application runtime itself. The safer boundary is therefore the public userscript bootstrap, which already owns v4.5.2/v4.5.3 browser-host hardening.

This amendment supersedes only the implementation-location/runtime-repin portions of `2026-08-19-v4.5.4-shell-ui.md`. The approved product behavior and verification requirements remain unchanged.

## Final architecture

`R4G3RUNN3R-Recruitment-Agency.user.js` v4.5.4 now owns a small shell enhancement layer after validating the existing immutable v4.5.0 application runtime.

The ten existing `@require` URLs remain pinned to the already-tested immutable runtime commit:

`9b22dc3478d7d57dba6ff3354681767b35cf0ba6`

`EXPECTED_APP_VERSION` therefore remains `4.5.0`. The public installer version becomes `4.5.4`.

### Scrolling

The bootstrap injects narrowly scoped CSS overrides after `RA_V45App.start()`:

- `.ra-shell` gets `min-height:0`;
- `.ra-main` gets `min-height:0` and `overflow:hidden`;
- `.ra-pagehead` becomes non-shrinking;
- `.ra-content` becomes the shrinkable `overflow:auto` viewport with an explicit visible scrollbar.

No routed page renderer changes.

### Sidebar Settings cleanup

The bootstrap removes only `#ra-nav [data-page="settings"]` after mount and observes `#ra-nav` so the duplicate is removed again after the core runtime rebuilds navigation during routing.

The Settings route itself and top-right `#ra-settings-button` remain untouched.

### Maximize / Restore

The bootstrap inserts `#ra-maximize` immediately before the title-bar Settings button and maintains transient session-only state:

- `maximized`
- `restoreGeometry`

Maximize captures and persists the current normal geometry, then applies a scoped `.ra-maximized` class that fills the viewport, disables CSS resizing and disables title-bar drag initiation.

Restore removes that class, clamps the saved normal geometry to the current viewport, reapplies it, and persists the restored normal geometry.

### Geometry-race protection

The core app already owns a debounced `ResizeObserver` that saves window geometry. Entering maximize could otherwise overwrite the saved normal geometry.

v4.5.4 protects that invariant in three ways:

1. clear any already-pending core geometry-save debounce before maximizing;
2. temporarily wrap `ResizeObserver` only while `RA_V45App.start()` constructs the app observer, suppressing callbacks for `#ra-app` while `.ra-maximized` is active, then restore the native constructor immediately after startup;
3. explicitly persist captured normal geometry on maximize and restored normal geometry on restore.

A window-capture `pointerdown` guard prevents the existing title-bar drag handler from starting while maximized.

## Verification

A dedicated real-Chromium regression, `tests/v45-browser-shell-ui.test.js`, executes the actual bootstrap and checks:

- no Settings button exists in sidebar navigation;
- top-right Settings still routes correctly;
- a deliberately tall routed page has `scrollHeight > clientHeight` and can scroll;
- Maximize fills the browser viewport;
- resizing is disabled while maximized;
- title-bar dragging cannot alter normal inline geometry while maximized;
- full-viewport dimensions are not persisted to IndexedDB;
- viewport resizing while maximized keeps the shell fitted;
- Restore returns to the prior normal geometry, clamped to the changed viewport;
- Maximize and Restore execute before the existing hostile document-capture click blocker.

Existing mobile, duplicate-world, DB upgrade, Torn-host, click-interference, unit and syntax regressions remain part of the full `npm test` / `npm run syntax` gate.

## Non-changes

This implementation does not change:

- `src/v45-app.js`;
- runtime `SCRIPT_VERSION` (`4.5.0`);
- DB version or stores;
- API rate/gap rules;
- pipeline semantics;
- Scout, forum discovery, Smart Match or Global Intelligence;
- the immutable runtime commit pins.
