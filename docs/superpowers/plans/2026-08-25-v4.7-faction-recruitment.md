# v4.7 Faction Recruitment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a complete, independently routed Faction Recruitment domain to Recruitment Agency without changing Company recruitment state or duplicating shared Torn player intelligence.

**Architecture:** Reuse the v4.6 shared `playerIntelligence` identity and existing `factionRecruitment` record, then add Faction-only core logic, additive IndexedDB support stores, operations, UI, workflow, Opportunity/Compare views, and platform routing. Faction Baseline controls `Invite Ready`; specialist profiles are optional matching contexts whose Hard failures affect only that profile. The public release is v4.7.0 and follows the existing two-phase source-merge then immutable-userscript-pin release process.

**Tech Stack:** Plain JavaScript UMD modules, IndexedDB, Node 20 `node:test`, jsdom/fake-indexeddb browser tests, Tampermonkey/Greasemonkey userscript metadata.

**Spec:** `docs/superpowers/specs/2026-08-24-v4.6-recruitment-platform-architecture-design.md`

## Global Constraints

- One Torn ID maps to one authoritative shared Player Intelligence record.
- Company and Faction recruitment records remain separate and never mutate each other.
- Faction pipeline is exactly: `Prospect`, `Contacted`, `Replied`, `Evaluating`, `Invite Ready`, `Joined`, `Rejected`, `Deferred`.
- Faction Baseline Hard failures block `Invite Ready` unless individually waived; they do not block Prospect/Contacted/Replied/Evaluating/Deferred.
- Specialist-profile Hard failures block eligibility for that specialist profile only; they never block `Invite Ready` when Faction Baseline is otherwise eligible.
- A manually pinned specialist profile is never silently replaced by rescoring.
- Do Not Contact remains a dedicated flag and messaging remains manual-send only.
- Torn API calls continue through the shared scheduler, max 75 calls/minute and minimum 800 ms between Recruitment Agency Torn API calls.
- Global Intelligence whitelist remains unchanged.
- Database migrations are additive. DB15 may create new stores but must not delete/reset DB13/DB14 stores.
- Settings remains title-bar only.
- Public v4.7.0 userscript `@require` entries must be immutable commit pins, never moving `main` URLs.

- [ ] **Step 3: Implement the core module with no Company dependency**

```js
const FACTION_STAGES=Object.freeze(['Prospect','Contacted','Replied','Evaluating','Invite Ready','Joined','Rejected','Deferred']);
const PROFILE_STATES=Object.freeze(['Draft','Active','Paused','Archived']);
const REQUIREMENT_KINDS=Object.freeze(['Hard','Preferred']);

function evaluateSpecialistProfile(rawProfile,facts={},waivers=[]){
  const profile=normalizeSpecialistProfile(rawProfile);
  const criteria=evaluateCriteria(profile.criteria,facts,waivers.filter(w=>String(w.profileId||'')===profile.profileId));
  const measured=profile.criteria.map(req=>({req,score:ratioScore(req,facts)})).filter(row=>row.score!==null);
  const weight=measured.reduce((sum,row)=>sum+(row.req.weight||1),0);
  const matchScore=weight?Math.round(measured.reduce((sum,row)=>sum+row.score*(row.req.weight||1),0)/weight):0;
  return {profileId:profile.profileId,matchScore,eligible:!criteria.hardFailed,criteria};
}

function suggestSpecialistProfile(profiles=[],evaluations=[],pinnedProfileId=''){
  const active=new Set(profiles.map(normalizeSpecialistProfile).filter(p=>p.status==='Active').map(p=>p.profileId));
  const eligible=evaluations.filter(e=>e?.eligible===true&&active.has(String(e.profileId||'')))
    .sort((a,b)=>Number(b.matchScore||0)-Number(a.matchScore||0)||String(a.profileId).localeCompare(String(b.profileId)));
  const suggestedProfileId=String(eligible[0]?.profileId||'');
  const pinnedProfileIdClean=String(pinnedProfileId||'').trim();
  return {suggestedProfileId,pinnedProfileId:pinnedProfileIdClean,bestChanged:Boolean(pinnedProfileIdClean&&suggestedProfileId&&pinnedProfileIdClean!==suggestedProfileId)};
}
```

`evaluateCriteria`, ratio scoring, freshness/Opportunity, stage-aging and Today-queue behaviour should follow the deterministic Company primitives but use only Faction names and Faction stages. `Invite Ready` gating must be exposed as a Faction-specific baseline result, not inferred from specialist eligibility.
