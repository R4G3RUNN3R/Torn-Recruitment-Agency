# v4.6 Company Recruitment Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the first complete Company Recruitment slice on top of the merged v4.6 Foundation: dedicated Company routes, authoritative Company candidate views, Company baseline requirements, vacancies, deterministic local eligibility/Match evaluation, and safe Hired-stage gating.

**Architecture:** Add a focused `v46-company-core.js` module for Company-only rules/evaluation, extend storage additively to DB14 for baseline/vacancy configuration, and wire new Company routes into the existing managed shell without changing the public v4.5.4 userscript pins. `companyRecruitment` becomes authoritative for Company workflow state while `candidateLocal` remains a compatibility mirror during transition. Shared `playerIntelligence` facts are read but never polluted with Company-private state.

**Tech Stack:** Plain JavaScript UMD modules, IndexedDB, Node test runner, fake-indexeddb/JSDOM/Puppeteer browser regressions, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-24-v4.6-recruitment-platform-architecture-design.md`

## Global Constraints

- One Torn ID = one authoritative shared Player Intelligence identity.
- Company Recruitment and Faction Recruitment remain separate domains.
- Company changes must never mutate Faction recruitment state.
- Public `R4G3RUNN3R-Recruitment-Agency.user.js` stays v4.5.4 with immutable `9b22dc3478d7d57dba6ff3354681767b35cf0ba6` runtime pins in this internal slice.
- Torn API hard ceiling remains 75 requests/minute with at least 800 ms between Recruitment Agency Torn API calls.
- Torn messages remain manual-send only.
- Global Intelligence whitelist remains unchanged.
- Database migration is additive only; no `deleteObjectStore`.
- Canonical Company pipeline order for new Company pages is `Not Contacted -> Contacted -> Replied -> Shortlisted -> Hired -> Rejected`.
- Existing v4.5 compatibility data is migrated/bridged without destructive reset.
