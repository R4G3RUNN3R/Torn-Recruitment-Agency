# Recruitment Agency v4.5 UI + Forum Discovery + Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v4.5.0 with the new Pythagoras-inspired clean-room application shell plus Forum Discovery, unified Candidates, six-stage Pipeline, Message Player, safe resumable sync, Settings/Data/Logs, and full privacy/regression protection.

**Architecture:** Preserve the existing Scout, Results, Global, and Match pure cores. Add a new pure `src/forum-core.js` for parsing, source normalization, merge precedence, pipeline validation, safe continuation, and message substitution. Keep IndexedDB/scheduler/DOM integration in the userscript, while introducing focused reusable UI helpers inside the userscript rather than rewriting the application into a framework.

**Tech Stack:** JavaScript userscript, Node 20 `node:test`, IndexedDB, official Torn v2 API, GitHub Actions.

## Global Constraints

- Userscript/package version target: `4.5.0`.
- IndexedDB version: `12`, additive only.
- Never call `deleteObjectStore`.
- Torn API hard maximum: `75` calls/minute.
- Minimum Recruitment Agency Torn API request gap: `800 ms`.
- All forum/company enrichment requests use the shared scheduler.
- Official Torn API only; no captcha/session bypass or unseen-page background scraping.
- Protected Recruit Scout backends remain forbidden.
- Smart Match remains local and consumes zero Torn API calls.
- Global Intelligence whitelist remains exactly: `playerId,name,observedAt,level,ee,activity30,xanax30,refills30,attacks30,rwHits30,networth,fit,fitType,lastActive,scoutStatus,sourceVersion`.
- Forum text, source URLs/history, pipeline stage, recruiter notes, salary, availability override, Match/Profile data, default/prepared messages, and workflow state remain local-only.
- Recruitment Agency never auto-submits Torn mail.
- Opening a profile/forum/message compose link never changes pipeline stage automatically.
- UI implementation is clean-room; reuse ideas and interaction patterns, not protected Pythagoras source code.
