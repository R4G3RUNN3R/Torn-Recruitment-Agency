# v4.6 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish the v4.6 storage, domain-boundary, migration, and navigation foundation required for separate Company and Faction recruitment while preserving one shared Player Intelligence identity per Torn ID.

**Architecture:** Add three focused v4.6 core modules rather than expanding the already-large `v45-app.js`: one for domain normalization, one for DB13/repository/backfill behavior, and one for collapsible navigation state. Existing v4.5 pages continue to function as the current Company-oriented workflow during this foundation slice; unfinished Faction, Workforce, Analytics, and advanced operational tabs are not exposed until their dedicated follow-on plans. The release is additive and migrates legacy data idempotently without deleting DB12 stores.

**Tech Stack:** Plain JavaScript userscript modules, IndexedDB, Node `node:test`, `fake-indexeddb`, JSDOM, Puppeteer/Chromium, GitHub Actions, Tampermonkey metadata `@require` modules.

**Spec:** `docs/superpowers/specs/2026-08-24-v4.6-recruitment-platform-architecture-design.md`

## Global Constraints

- One Torn ID = one authoritative shared Player Intelligence identity.
- Company Recruitment and Faction Recruitment are separate domains.
- A Company-only discovery must never create a Faction Recruitment record; the inverse rule applies to Faction discovery.
- Shared Scout/intelligence refreshes update shared player truth once; domain state is not overwritten by intelligence refresh.
- No automatic or bulk Torn message sending.
- Maximum 75 Torn API calls/minute and minimum 800 ms spacing remain unchanged.
- All Torn API work continues through the existing shared scheduler.
- Database migration is additive only; do not call `deleteObjectStore()` and do not reset existing DB12 data.
- Global Intelligence whitelist remains unchanged.
- Settings remains title-bar-only; no sidebar Settings entry.
- Preserve v4.5.4 internal scrolling, Maximize/Restore, hostile-click shielding, mobile behavior, launcher behavior, and geometry persistence.
- Do not silently reorder the current runtime Company pipeline during this foundation slice.
- Do not expose unfinished Faction/Workforce/Analytics pages as dead or “coming soon” tabs.

```js
const COMPANY_DEFAULT_STAGE = 'Not Contacted';
const FACTION_DEFAULT_STAGE = 'Prospect';

function normalizeUserId(value) {
  const userId = String(value ?? '').trim();
  if (!/^\d+$/.test(userId) || Number(userId) <= 0) throw new Error('A valid Torn player ID is required.');
  return userId;
}

function mergePlayerIntelligence(existing, patch = {}, source = 'unknown', now = Date.now()) {
  const userId = normalizeUserId(patch.userId ?? existing?.userId);
  const previousSources = Array.isArray(existing?.sources) ? existing.sources : [];
  const sources = [...new Set([...previousSources, String(source || 'unknown')])];
  return {
    ...(existing || {}),
    ...patch,
    userId,
    name:String(patch.name ?? existing?.name ?? '').trim(),
    sources,
    createdAt:Number(existing?.createdAt || now),
    updatedAt:Number(now)
  };
}
```

`normalizeCompanyRecruitment()` must preserve existing v4.5 Company fields (`pipelineStage`, `availability`, `desiredCompany`, `desiredRole`, `expectedSalary`, `recruiterNote`, `manualFields`, `discoverySources`, `latestForumSourceId`, `createdAt`, `updatedAt`) and add `domain:'company'`, `archived:false` by default, and `cycles:[]` by default. Do not reorder/renormalize a valid current v4.5 stage beyond the existing six accepted values.

`normalizeFactionRecruitment()` must use `domain:'faction'`, default stage `Prospect`, `archived:false`, `cycles:[]`, independent note/tag/follow-up containers, and must not copy Company-only salary or vacancy fields.

`legacyCandidateToCompany()` must be a thin call to `normalizeCompanyRecruitment()` and must never manufacture a Faction record.

async function ensurePlayer(userId, patch = {}, source = 'manual', now = Date.now()) {
