# Recruitment Agency v4.7.4 - Bootstrap Ownership Hotfix

## Problem

User testing showed that navigation behaviour could remain unchanged across newer releases even while repository/browser tests passed. The public bootstrap used a shared DOM owner marker but returned immediately whenever that marker existed, regardless of which Recruitment Agency version owned it. An older in-memory or duplicate instance could therefore remain authoritative while a newer build silently did nothing.

## Fix

- Compare the existing shared DOM owner with the current installer version.
- Same-version duplicate worlds still return immediately.
- An older/different owner triggers one clean page reload to flush stale in-memory code.
- If the different owner persists after that reload, report the exact conflicting version and do not run two versions concurrently.
- Preserve all existing route-state, navigation scoping, privacy, DB15 and Company/Faction isolation protections.

## Regression coverage

The regression suite proves that stale-owner recovery exists and that a persistent older owner is surfaced explicitly rather than silently winning forever. Existing routing, real Chrome, Torn-host, isolated userscript world and database-upgrade coverage remains enabled.

The reviewed immutable v4.7.4 runtime source is `999a2f9eafd28891dc5de461f08b1d29bbd41eea`; the public release wrapper must pin all 29 runtime modules to that exact commit.
