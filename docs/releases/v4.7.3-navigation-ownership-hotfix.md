# Recruitment Agency v4.7.3 - Navigation Ownership Hotfix

Date: 26 August 2026

## Status

This release supersedes v4.7.2 for the live Company Overview snapback defect. v4.7.2 correctly made canonical route state synchronous and protected newer routes from stale asynchronous renders, but user testing proved that a separate live trigger remained.

## Root cause reproduced

The Recruitment Agency sidebar rebuild used document-global `document.querySelectorAll('[data-page]')` and `document.querySelectorAll('[data-nav-toggle]')` bindings. Torn-owned controls using the same attributes could therefore be assigned Recruitment Agency click handlers. Unknown live route values were normalized by the Recruitment Agency navigation helper to `company-overview`.

A regression on unchanged v4.7.2 reproduced the exact failure: while on `faction-candidates`, clicking a foreign Torn-style `data-page="2"` control changed canonical Recruitment Agency state to `company-overview`. The same diagnostic also proved that the Recruitment Agency overwrote the foreign control's own click handler.

## Fix

- Navigation and group-toggle binding is scoped to `#ra-nav` only.
- Active-route highlighting is also scoped to `#ra-nav`.
- Torn-owned controls outside Recruitment Agency retain their own handlers.
- Live route requests are accepted only when they are explicit Recruitment Agency routes visible for the current complexity mode. Invalid live route values return without changing the active page.
- Startup/restoration still uses the existing normalization path so legacy persisted route values remain recoverable.

## Verification

Before packaging, the clean behavior branch passed 280/280 tests plus the full JavaScript syntax gate. New coverage includes:

- exact foreign-control `faction-candidates -> company-overview` red-to-green regression;
- invalid live-route rejection without page mutation;
- real Chrome with the public userscript bootstrap, physically clicking Faction Requirements -> Add Requirement -> Create Specialist Profile while remaining on Faction Requirements;
- a Tampermonkey-like CDP isolated userscript world performing the same physical in-page interactions;
- existing real Torn-host, isolated-world, DB11->DB15 migration, Company/Faction isolation, privacy, API pacing, and manual-messaging checks.

The public release pins all 29 runtime modules to immutable source commit `6da014279063cca945aad399af8dadc28ce0e859`.

No database migration is required. DB15 is unchanged. No Recruitment Agency data reset is required.
