# v4.7.2 Route Authority Hotfix

## Status

v4.7.2 supersedes v4.7.1 for the live recruitment navigation snapback bug.

v4.7.1 fixed a downstream Faction control symptom, but it did not remove the underlying split route-authority race. Company and Faction platform bindings could bypass the central router, begin asynchronous IndexedDB rendering, and leave the canonical route temporarily set to the previous page, commonly `company-overview`.

## Root cause

Recruitment navigation had three competing route paths:

1. the base application central router;
2. Company platform navigation overrides;
3. Faction platform navigation overrides.

The central router committed `state.page` before asynchronous work. The Company and Faction platform paths did not. Their route state was persisted only after asynchronous rendering had already begun, allowing controls or older renders to observe and restore stale route state.

A regression test reproduced this before the production fix: clicking Company Candidates began rendering that page while canonical `state.page` was still `company-overview`.

## Fix

- The central application router is the canonical route authority.
- Company and Faction sidebar and in-page navigation delegate to the central router.
- The selected route is committed synchronously before asynchronous database/render work.
- Centrally routed platform renders buffer output and refuse to repaint if a newer route has become canonical before the older render finishes.
- Standalone platform renderer tests remain supported outside the centrally routed application.

## Regression coverage

The release adds direct tests proving:

- Company navigation commits canonical route state in the same click turn.
- Faction navigation commits canonical route state in the same click turn.
- A newer cross-domain route wins over an older asynchronous render.

Existing browser coverage remains in place for real Chrome hit-testing, isolated userscript execution, the live Torn host, mobile routing, and DB11-to-DB15 upgrade behavior.
