# v4.7.5 Dark-Theme Readability Hotfix

Date: 26 August 2026

## User-visible defect

On Torn dark pages, host CSS could override Recruitment Agency table and Settings text colors. Company/Faction candidate data then rendered black against near-black Recruitment Agency panels, making the workspace effectively unreadable.

## Reproduction

A real-Chrome regression injects hostile Torn-style text rules after Recruitment Agency's normal application styles and verifies computed colors rather than checking CSS strings only. The regression failed against the untouched v4.7.4 public shell before the production fix.

## Fix

The public shell now applies scoped `#ra-app` contrast protection:

- primary table body text: bright green accent `#67e38c`
- secondary/muted table text: readable muted `#9aaa9f`
- table controls: bright `#edf4ef`
- Settings section headings, labels, and form values: bright green accent `#67e38c`
- Danger Zone heading: red `#e65d62`

The overrides use `!important` only on the shell-level selectors that must defeat host-page styling. They do not change Recruitment Agency data, routing, domain logic, or storage.

## Verification

The release must pass the full serialized Node/browser suite plus JavaScript syntax checks. The new readability regression is part of that gate and specifically asserts computed styles after hostile host CSS is injected.
